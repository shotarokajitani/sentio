# スライスCH — 列名の行が無いCSVを、プロンプトに入る前に断る

- 状態: **active**（2026-08-31 梶谷さん承認・案(b)）
- 起草: 2026-08-31（検収者）
- 背景: `docs/reports/2026-08-31_CSV_ヘッダー行前提が崩れる.md`

## なぜやるか

**`connect-client.tsx:139` は1行目を無条件に列名として扱う。**

```ts
const headers = parseCSVLine(lines[0]);
```

列名は `/api/csv/analyze` のプロンプトに `- "${h}": 型=…` の形で**そのまま載る**
（`route.ts:34-44`）。

2026-08-31、全銀協規定フォーマット系の入出金明細（**列名の行が無い**）が投入され、
**銀行名・支店名・口座番号・口座名義が「列名」として Anthropic API に送られた。**

`route.ts` にはこう書いてある。

> Build column description for Claude (**no string cell values - PII protection**)

**この保護は「1行目が列名である」ことに依存していた。**
文字列セルのサンプル除外は効いていたが、**列名そのものには一切効いていない。**
防いでいたのではなく、**防いでいるつもりだった**が正確である。

送信先は `/privacy` §4 に副処理者として記載済みの Anthropic であり第三者流出ではない。
**それでも、設計が意図していない経路が開いていた。**

## 決定

| # | 論点 | 決定 |
| --- | --- | --- |
| **CH-D1** | 全銀協フォーマットを取り込むか | **取り込まない。検出して断る**（梶谷さん判断・案(b)）。レコード区分ベースのパーサは別スライス。**いまは穴を塞ぐことだけをやる** |
| **CH-D2** | どこで止めるか | **クライアント側で、`fetch` を出す前に止める。** これが「プロンプトに入らない」ことを保証できる唯一の位置である。**加えてサーバ側でも同じ判定を行う**（API は直接叩ける。多層で閉じる） |
| **CH-D3** | 判定ロジックの置き場所 | **`shared/` の純関数**。クライアントとサーバが**同じ実装**を読む（スライスWM の WM-D1 と同じ形）。二重実装すると片方だけ直したときに穴が開く |
| **CH-D4** | 判定の基準 | 1行目のセルのうち、**数値のみ・日付として解釈可能・空** のいずれかであるものを「列名らしくない」と数える。**その割合が半数以上なら列名の行ではない**と判定する |
| **CH-D5** | 半角カナを判定に使うか | **使わない。** 列名に半角カナを使う会計ソフトの書き出しがありうる。**数値・日付・空の3つだけで足りる**（今回の実物は17列中14がこれに該当する） |
| **CH-D6** | サーバ側が返すステータス | **400**（呼び出し側の誤り）。**500 にしない。** 500 は「Sentio 側が壊れている」を意味し、今回は壊れていない |
| **CH-D7** | 文言 | 「列の対応を推定できませんでした」と**別の文にする**。この1文は既に4つの別原因を飲み込んでおり、**もう1つ足すと診断不能になる** |
| **CH-D8** | 既に送られた分の扱い | **追えない。** Anthropic 側のログは Sentio から消せない。**記録として残すだけにする**（`docs/reports/2026-08-31_CSV_ヘッダー行前提が崩れる.md`）。実データを持つのは顧客0号（自社）のみで、外部顧客はまだ居ない |

## 判定の形（**`shared/csv/header-guard.ts`**）

```ts
/** 1行目が列名の行に見えるか。false なら送信前に止める */
export function looksLikeHeaderRow(cells: string[]): boolean

/** 判定の内訳。文言と検査で使う */
export interface HeaderRowVerdict {
  isHeader: boolean;
  total: number;
  nonNameLike: number;   // 数値のみ / 日付 / 空 の数
}
```

- **空配列・1セルだけ**のときの扱いを決めて、テストで固定すること
- 「数値のみ」はカンマ区切りの桁（`1,903,748`）と符号・小数点を含めて判定する
- 「日付」は `2026-08-01` / `2026/8/1` / `20260801` / `80830` のような形を含める。
  **どこまでを日付と見なすかを実装で決め、テストで固定する**

## 受入基準

### CH-1 系: 断る

| # | 基準 | 検証 |
| --- | --- | --- |
| CH-1-1 | 全銀協フォーマット系の1行目（**実物と同じ形**）で `isHeader === false` になる | unit |
| CH-1-2 | **クライアントが `/api/csv/analyze` を呼ばない。** `fetch` が1回も走らないこと | unit（**陰性コントロール。これが本体**） |
| CH-1-3 | サーバも同じ入力を **400** で断る。**500 にしない** | unit |
| CH-1-4 | 400 の応答本文に**入力セルの中身を含めない**。件数と割合だけを返す | unit（**陰性コントロール。エラー本文経由の再流出を防ぐ**） |

### CH-2 系: 通す（**誤検知を出さない**）

| # | 基準 | 検証 |
| --- | --- | --- |
| CH-2-1 | `取引日,摘要,お支払金額,お預り金額,差引残高` が `isHeader === true` | unit（**陰性コントロール**） |
| CH-2-2 | Stripe の `created,description,amount,fee,net,type` が `true` | unit（**陰性コントロール**） |
| CH-2-3 | 弥生の `仕訳日付,借方金額,貸方金額,摘要` が `true` | unit（**陰性コントロール**） |
| CH-2-4 | 列名に年月が混ざる形（`項目,2026年8月,2026年9月`）が `true`。**半数未満なので通る** | unit（**境界。閾値の意味をテストで固定する**） |
| CH-2-5 | あおぞら銀行の**列名付き**入出金明細CSV（2026-08-31 に本番で取り込みに成功した形）が `true` | unit |

### CH-3 系: 壊してはいけないもの

| # | 基準 | 検証 |
| --- | --- | --- |
| CH-3-1 | 列名の行があるCSVの取り込み経路が**1文字も変わらない** | 既存テストが通ること |
| CH-3-2 | 判定の実装が**1つ**であること。クライアントとサーバが同じ関数を読む | 目視＋`check:edge-types` / `typecheck` の両方が通ること |
| CH-3-3 | `route.ts` の設定チェック（`ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` 未設定で 500）を**判定より前**に残す | unit |

## 文言（`src/i18n/ja.ts` の `csv`）

```ts
noHeaderRowTitle: "列名の行が見つかりませんでした",
noHeaderRowBody:
  "1行目がデータで始まっています。全銀協フォーマットなど、列名の行が無い形式には対応していません。"
  + "列名つきで書き出したCSVをお試しください。",
```

**「別のCSVでお試しください」と書かない。** それでは何を直せばいいのか分からない。
**「列名の行が無い」という事実を伝える。**

## 停止点

- **merge しない。** PR を全緑にした時点で止まって報告する
- **全銀協フォーマットのパーサを書かない**（CH-D1）
- **判定の閾値を env や設定で可変にしない。** 定数1つで固定する
- 既存の「列の対応を推定できませんでした」の経路を**まとめて作り直さない。**
  今回足すのは**新しい1本の分岐だけ**である
- 実データ（口座番号・名義・銀行支店名）を**テストフィクスチャに書かない。**
  実物と**同じ形**の架空値を使うこと（`1903748` ではなく `9999999`、
  `ｶ)ﾃﾞｲｾ-ﾉ` ではなく `ｶ)ﾃｽﾄ` など）

## 非スコープ（**やらない**）

- 全銀協フォーマットの取り込み対応（別スライス。`07_open_items.md` に登録する）
- Shift-JIS の文字化け検出
- 「列の対応を推定できませんでした」が飲み込んでいる残り3原因の切り分け
  （鍵未設定 / 鍵の種類違い / モデルが JSON を返さない）。**別で立てる**
- `route.ts` の `raw` を画面に出すこと。**出すべきかは未判断**（モデルの生成文であり、
  入力を復唱している可能性がある）

## この契約が閉じたら分かること

**「PII protection と書いたコメントが、何を前提にしていたか。」**

コメントは嘘ではなかった。**前提が明示されていなかっただけである。**
前提が崩れる入力は、利用者が普通に持っている（銀行がその形式で書き出す）。
このスライスは、**コメントが主張していた保護を、実際に成立させる。**
