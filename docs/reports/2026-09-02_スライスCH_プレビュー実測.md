# スライスCH をデプロイ環境で実測した（2026-09-02）

**8月31日にできなかった実測が、Preview に Anthropic の設定が入ったことで取れた。**
断る側（CH-1-3 / CH-1-4）と通す側（CH-2-5）の両方を、実際に動いている環境で確かめている。

## 前提: Preview の設定が入った

8月31日の時点では設定が無く、**設定チェック（CH-3-3）で 500 に落ちて判定まで到達しなかった。**

```
2026-08-31  POST /api/csv/analyze {} → 500 {"error":"ANTHROPIC_API_KEY / ANTHROPIC_MODEL not set"}
2026-09-02  POST /api/csv/analyze {} → 400 {"error":"headers required"}   (1.29s)
```

**500 → 400 に変わったことが、設定チェックを通過した証拠**である
（`docs/reports/2026-08-31_CSV列推定の復旧実測.md` の段階1 と同じ見方）。
この探りは Anthropic のトークンを1つも使わない。

## CH-1-3: 列名の行が無い入力を 400 で断る（**500 にしない**）

全銀協フォーマット系の1行目（**実物ではなく架空値**）を投げた。

```
status=400  time=0.456s
{"error":"no_header_row","total":17,"non_name_like":14,"ratio":0.82}
```

- **400 である。** 500 ではない（CH-D6。Sentio が壊れているのではなく、入力の形が違う）
- **0.46秒。** LLM を通っていない。プロンプトを組む前に断っている
- 内訳（17列中14・0.82）が、ユニットテストの実測値と一致している

## CH-1-4: 応答に入力セルの中身を含めない

```
本文のキー           : ["error", "non_name_like", "ratio", "total"]
識別性のあるセルの漏れ: なし
カナ・口座番号の漏れ  : なし（ｼﾞ-ｴﾑｵ-ﾃｽﾄ / ﾎｳｼﾞﾝﾀﾞｲﾆ / ｶ)ﾃｽﾄ / 9999999 / 123821 いずれも本文に無い）
```

**塞いだ経路が、エラー本文で開き直していないことを実環境で確認した。**

## CH-2-5: あおぞらの実物の列名は通る（**誤検知を出していない**）

2026-09-01 に確認した実ファイルの列名で、**実際に LLM を通した**。

```
status=200  time=2.12s
{"mapping":{"date":"日付","description":"摘要","amount":null,"direction":null,
            "credit":"入金金額","debit":"出金金額","balance":"残高"}}
```

**マッピングは正しい。** 入金・出金が別列の形を、`amount` / `direction` を null にして
`credit` / `debit` に振り分けている（`route.ts` のプロンプトが指示しているとおり）。

### 併せて: 応答時間が 30秒 → 2.1秒 になっている

2026-08-31 の復旧実測では、5列の銀行明細で **30,105ms** かかっていた
（`docs/reports/2026-08-31_CSV列推定の復旧実測.md`）。同じ経路が今回 **2,122ms** である。

**この差の原因は特定していない。** モデルの応答速度・Vercel のリージョン・
コールドスタートの有無など複数の要因がありうる。
ただし当時「30秒は遅い。列数が多い実ファイルでは関数タイムアウトに当たる可能性がある」
と記録した懸念は、**少なくとも今日の実測では顕在化していない。**
6列・59行の実ファイル相当で 2.1秒である。

## この記録がしていないこと

- **実ファイルそのものは投入していない。** 列名と型統計だけを送っている
  （明細の中身は本番のデータであり、検証のために動かすものではない）
- 30秒 → 2.1秒 の**原因は追っていない**。速くなったことを事実として記録しただけである
