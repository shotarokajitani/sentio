```markdown
## チャット非依存シグナル設計（2026-07-23 確定）

チャット依存の検出設計はターゲット層の約8割で機能しない（従業員99人以下のビジネスチャット導入率21.6%——日経BPコンサルティング 2024年10月。中小企業で仕事にプライベートチャットを使う層は83.6%——kubell 2024年11月）。以下はチャット非依存の代替検出元。

| シグナル | 旧（チャット依存） | 新（チャット非依存） |
|---|---|---|
| 特定個人の孤立 | 発言数の減少 | カレンダー: 1on1・定例の消滅 ／ 勤怠: 連続休暇・打刻時間の変化 |
| 現場の疲弊 | 深夜メッセージ比率 | 勤怠: 特定部門の残業偏り・休憩取得の崩れ |
| 内製体制の崩れ | 会話量の変化 | 会計: 外注費の急増・人件費構成の変化 |
| 社外関係の途絶 | ルーム活動停止 | カレンダー: 特定取引先との接触消滅 ／ メールメタデータ: 往復頻度 |

※閾値・検出ロジックの詳細は次セッションで確定。
```

### 3-3. Evaluator基準の追加

既存5基準のリスト（L26-31）に6番目を追加:

```
  6 カバレッジ: カバレッジ不足時は断定しない（未接続データ源に依存する推論は確度を明示的に下げる）
```

**判断理由**: 既存5基準は独立した評価軸として並列されている。カバレッジ不足時の断定回避は、基準4「トーン: 断定しない」の下位条件とも解釈できるが、トーンは表現の問題、カバレッジは証拠の充足性の問題であり性質が異なる。6番目の独立基準として追加する。この判断理由はコミットメッセージに記載する。

### 3-4. Evaluator較正信号の制限

「コスト・較正」セクション内の較正ループ記述の後に:

```markdown
### 較正信号の制限（2026-07-23 確定）

較正信号として使用してよいもの: 開封率・返答率・「知らなかった」率

較正信号に含めてはならないもの: 相談ボタンの押下率・導入支援の成約

理由: 押下率を較正に用いると、意図せず「相談を誘発しやすい問い」のスコアが上昇し続ける。事後の原因特定と巻き戻しが困難なため、設計段階で遮断する。
```

## 相談ボタン（pull側）

push 4枠（パルス/即時/週次/月次）+ pull 1（Sentioに聞く）の原則において、相談ボタンはpull側に属する。

| 項目 | 仕様 |

| 収益の開示 | 相談カード画面で初めて費用を提示する |
| 未押下時 | 何も起きない。催促しない。再表示は既存の間隔統制（同一ツールへの提案は2週間に1回まで）に従う |
