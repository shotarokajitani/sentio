# S-4-2 後半「本番の実 Function URL へ認証なしで 401」— 実測結果

実施日: 2026-08-20 / 実施者: 検収者（Cowork・Claude in Chrome 経由）
対象: 本番 `kwpldqbnkraftaahnpev`
前提: `deploy #27`（`7a455be` / PR #31）完了後。17本すべてから `--no-verify-jwt` を外した状態

## 判定: **合格**

無認証のリクエストがゲートウェイ層で 401 になり、本文にデータが一切含まれないことを確認した。

## 実測

Chrome の DevTools ネットワーク記録から取得した実ステータス。

| # | URL | method | statusCode |
| --- | --- | --- | --- |
| 1 | `https://kwpldqbnkraftaahnpev.supabase.co/functions/v1/state-memory-packet` | GET | **401** |
| 2 | `https://kwpldqbnkraftaahnpev.supabase.co/functions/v1/investigate` | GET | **401** |

応答本文（`state-memory-packet`）:

```json
{"error":"unauthorized"}
```

## 修復前との対比（ここが要点）

**同じ URL が、修復前は 200 で本番の実データを返していた。**

| 時点 | statusCode | 本文 |
| --- | --- | --- |
| 修復前（`--no-verify-jwt` あり） | **200** | 本番会社の活動タイムライン **824文字** |
| 修復後（本実測） | **401** | `{"error":"unauthorized"}` のみ |

無認証で本番データが読める窓は閉じた。

## この実測でカバーできていない範囲

1. **17本すべてを叩いたわけではない。** 2本のみ。
   ただし `--no-verify-jwt` の除去は `deploy.yml` の共通処理であり、
   適用漏れは `check:caller-guard`（契約 S-4-8）が CI で機械検出している
   （ci #86 で「デプロイ対象 17本すべてが resolveCaller を通っている」）。
   **全数を手で叩くのではなく、検査器で担保する設計**である

2. **`sync-connections` は叩いていない。**
   自動モードの分類器に拒否された。実運用中の唯一の cron 対象であり、
   401 の確認は停止点2-b（`net._http_response.status_code` が 200、
   または Invocations に 401 が無いこと）で別途行う

3. **GET のみ。POST は未実測。**
   ゲートウェイ層の JWT 検証はメソッドに依存しないが、実測はしていない

4. **Supabase ダッシュボードの Invocations 画面は自動操作タブで白紙になる**（実測）。
   ログ経由の確認は人間の手が要る
