# Sentio 機能設計書 v2 — 概要（正本）
更新: 2026-07-02 / 出典: 設計議論の確定事項のみ。推測を含まない。

## 1. 核
- 定義: 誰にも報告させず・入力させずに会社の状態を吸い上げ、判断に変える。収集が前半、翻訳が後半。
- 根拠となる市場事実: SFA/CRM利用企業の43.6%が「入力・更新が複雑」、40.6%が「メンバーが入力しない」を課題（Mazrica調査）。入力依存が失敗の主因。
- 顧客インパクト: 「見える！」。BIが見せるのは数字、Sentioが見せるのは意味と気配。
- 品質基準（Evaluatorハード閾値）: 「読んだ経営者の頭に、自社の状態が一枚の絵として浮かぶか」。新奇性は加点に降格。
- 内部北極星: アンチ・セールスフォース（非公式・対外不使用）。

## 2. 性悪説4原則
1. 従業員はゼロ入力（データは業務の排気: 会計/受注/カレンダー/メッセージのメタデータ/勤怠）
2. 沈黙をシグナルにする（返信遅延・発言減・連絡途絶＝挙がってこないこと自体を検知）
3. 経営者にも性悪説（読む→動くのコストをワンタップで潰す）
4. 監視への防衛行動まで予測する（監視化はデータ源を自壊させる設計ミス）

## 3. 開示境界（確定）
従業員への開示は3点のみ: ①ツールの存在 ②目的（報告負担を減らす） ③メッセージ本文は取得しない。
検知ロジック・閾値・個別シグナルは非開示。告知は「日報と報告会議を減らします」という負担削減の通知。
出力は評価・査定文脈を禁止、ケア文脈のみ（entitiesの用途制限フラグで構造化）。

## 4. データ源の二層構造
- 初速を作る層: URL解析＋外部公開データ（接続ゼロで動く。Day0体験を担う）
- 解約を防ぐ層: 行動排気データ（参入障壁。継続率を担う）
- 主柱は取引記録型（EC/POS/販売管理）。入力依存型（SFA/CRM）は補助。
- KPI: 初週にカレンダー・会計・CSVのいずれか1本接続。

## 5. 4層アーキテクチャ
Ingest → State → Sense → Act（詳細は 01〜04）。下層が上層のスキーマを規定する。

## 6. 体験（プッシュ4枠＋プル1本）
統制原則: 「毎日見えるが、毎日読まされない」。割り込みの権利は緊急度が買う。
Day0初回調査バッチ / デイリーパルス（3行・10秒）/ 即時アラート（機械的事実のみ）/
週次「今週の会社」（主戦場）/ 月次レーダー / プル「Sentioに聞く」（無制限・証拠遡及可）。

## 7. North Star
「週1回以上、Sentio起点の行動（ワンタップ実行・返信・質問）が発生している会社の割合」。
副指標: 平均カバレッジ（ベースライン成立指標数）。

## 8. フェーズ
Phase1 鏡（本スコープ）→ Phase2 番人（続報・較正の主役化）→ Phase3 参謀（横断パターン。匿名化設計は未確定＝07参照）。

## 9. Sentio禁じ手（確定事項の条文化・Lauda憲章形式を採用）
1. 入力を要求しない — 機能が従業員・経営者の手入力を前提にした瞬間、設計をやり直す（アンチSF）
2. 本文を取得しない — S2に本文フィールドは構造上存在しない。allowlist検査で機械的に強制
3. 監視ツールにしない — 3点開示を破らない。従業員が絡む出力はケア文脈のみ（care_onlyフラグ）
4. 勝手に送らない・登録しない — ワンタップは下書き/仮登録で停止。最終確定は常に経営者
5. 解釈をimmediateで送らない — 即時アラートは機械的事実の専用資格。LLM生成物は昇格禁止
6. 見えているふりをしない — カバレッジ添付・鮮度切れの即時除外・冷間期の確度表示。「安定」と「見えていないだけ」を混ぜない
7. 証拠なき断定をしない — Findingの全主張は証拠イベントIDに遡れなければ配信しない（Evaluator基準2）
8. 記憶を勝手に確定させない — 記銘は3経路のみ・訂正経路必須。07未確定事項を実装で先取りしない
9. 誠実さ・安全の機構を課金壁に入れない — 3点開示・透明性ページ・カバレッジ/鮮度の正直表示・冷間期確度表示・
   証拠遡及・ケア文脈制限・「勝手に送らない」・fail-closed・進行中損失カテゴリの即時通知は全プラン標準。
   課金軸は価値の深度・速度・広さ（調査予算・会話・レーダー・属性範囲・非損失系の即時性）のみ
   （2026-07-02採用。Lauda禁じ手6と同文＝ディセーノ共通条文候補）
