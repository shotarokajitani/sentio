# スライスBU — 購読の導線を作る（API はあるが、押す場所が無い）

- 状態: **active**（2026-09-02 梶谷さん承認）
- 起草: 2026-09-02（検収者）
- 前提: `/api/billing/checkout` と `/api/billing/webhook` は実装済み・本番で疎通確認済み

## なぜやるか

**API は動くが、利用者が押せる場所がどこにも無い。**

```
$ grep -r "billing" src/
src/app/api/billing/checkout/route.ts
src/app/api/billing/webhook/route.ts
（UI からの参照は 0件）
```

`/connect` にも購読の節が無い。**課金のコードは本番に入っているが、
1円も課金できない**のはこれが理由である。

### 本番で疎通は確認済み（2026-09-02）

```
POST /api/billing/checkout → 200
→ https://checkout.stripe.com/c/pay/cs_live_...
```

`STRIPE_SECRET_KEY` / `STRIPE_PRICE_STANDARD` / `NEXT_PUBLIC_SITE_ORIGIN` は
正しく効いている。**Webhook だけが未検証**で、それは購読を1回通さないと確かめられない。

## 通しの検証（**merge 前・Preview で行う**）

この PR の Preview URL が決まったら、次の順で確かめる。**梶谷さんの操作が要る。**

1. Stripe の**テストモード**で Webhook を登録する
   送信先 `https://<この PR の Preview URL>/api/billing/webhook`
2. Vercel の **Preview 環境**にテスト用の値を入れる
   （`rk_test_...` / テストの `price_...` / テストの `whsec_...` /
   `NEXT_PUBLIC_SITE_ORIGIN` は Preview の URL）
3. Preview の `/connect` で購読ボタンを押し、**テストカード** `4242 4242 4242 4242` で確定
4. `/connect?billing=done` に戻る
5. **Supabase の Authentication → Users** で、そのユーザーの
   `user_metadata.subscription.status` が `active` になっていることを見る

**5 が変わらなければ Webhook が届いていない。** Stripe の Webhook ログで
配信の成否と応答コードを見る。**401 なら署名シークレットの不一致**である。

## 非スコープ（**やらない**）

- 解約・プラン変更の導線（Stripe カスタマーポータル）
- 請求書の表示、支払い履歴
- `DEFAULT_PLAN` を `TRIAL_PLAN` に倒すこと（**Stripe が回り始めてから**。
  いま倒すと既存の会社の枠を黙って 10 → 5 に減らす）
- 拡張プラン（`09_pricing.md` で「置かない」と決めている）

## この契約が閉じたら分かること

**署名シークレットが正しいかどうか。**

`checkout` は本番で通ることを確かめた。**`webhook` はまだ一度も呼ばれていない。**
購読を1回通して初めて、「Stripe が Sentio に通知を届けられる」ことが実測になる。
それが確かめられるまで、**課金は「動くはず」の状態にとどまる。**
