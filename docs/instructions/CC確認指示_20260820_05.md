## 【2】判断3件への回答

### 判断(1) — Q8 は **案2 ＋ 案1** を採用します（梶谷さん承認済み）

`~/.claude/settings.json` の編集を**許可します。** ただし全プロジェクトに影響する
個人設定なので、次の順序を厳守してください。

#### 手順

1. **先にバックアップを取り、パスを報告する**
   （例: `~/.claude/settings.json.bak-20260820`）

2. **PostToolUse フックが実際に受け取る入力を実測する。**
   `$CLAUDE_FILE_PATHS` のような環境変数を**記憶で使わないこと。**
   現行の Claude Code は PostToolUse に JSON を **stdin** で渡し、
   `tool_input.file_path` に編集先が入るはずですが、**キー名も含めて実測で確かめてください。**
   一時的に「stdin をそのままファイルに落とすだけ」のフックを仕込んで
   Write を1回行い、**受け取った JSON の全文を報告**すること

3. 実測した構造に基づいてフックを書き換える。要件は3つ
   - **対象は編集された1ファイルのみ。** `prettier --write .` の `.` をやめる
   - **失敗を握りつぶさない。** 現状の `2>/dev/null` は外してください。
     ただし作業をブロックはしないので、終了コードは 0 に丸めて構いません
     （stderr には出す）。「失敗しても気づけない」状態を残さないことが要件です
   - **Windows で動くこと。** `jq` に依存しないこと（node で書く）

4. **検証を実測で行う**
   - 変更後の `~/.claude/settings.json` が JSON として妥当であること
   - Sentio で Write を1回行い、**その1ファイルだけ**が整形されること
   - **`git status --porcelain` に無関係ファイルが出ないこと**
   - `docs/checklists/env-diff.md` を Write で1回触って、**表が壊れないこと**
     （これが今回の本丸です）

5. **案1 も併せて入れる。** `.prettierignore` に
   `docs/checklists/env-diff.md` を追加してください。
   Bash 経由で `prettier --write .` を回した場合の保険です

6. フックが壊れた場合に自力復旧できなくなる経路がないか確認してください。
   PostToolUse なので Write 自体はブロックされないはずですが、
   **JSON が壊れた場合に Claude Code が起動できなくなる**なら、
   バックアップからの戻し方を報告に明記すること
