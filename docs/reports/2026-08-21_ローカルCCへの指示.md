## 補足: Docker を外す判断（2026-08-21）

容量のため PC から Docker を外す。**Sentio の開発と CI は成立する。**

| 用途                               | Docker 無しでどうなるか                                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `pnpm dev`（`next dev`）           | **影響なし。** アプリはコンテナ化していない（`Dockerfile` / `docker-compose*` は 0件）                       |
| Vercel へのデプロイ                | **影響なし**                                                                                                 |
| CI（GitHub Actions）               | **影響なし。** ランナー側に Docker がある。`ci.integration` が `supabase start` → `supabase db reset` を回す |
| `check:allowlist` / `check:schema` | **ローカル不可になる。** CI の `ci.integration` のみ                                                         |
| 全 migration の素通し適用          | **ローカル不可になる。** CI のみ（`.github/workflows/ci.yml:80` に明記の通り、元々そこが唯一の全適用検証）   |
| `check:edge-types`                 | Docker ではなく Deno v2.1.4 が前提。Deno 単体を入れればローカルでも可                                        |

**失うのは「ローカルでの実DB検査」だけで、担保そのものは失われない。**
`docs/reports/2026-08-20_現状サマリ.md` §6 の時点で検収者（Cowork）は
すでに psql / Docker / Deno 無しで回しており、体制としては既存の分担に寄るだけである。

**代償**: 実DB検査のフィードバックが「ローカル数十秒」から「PR を立てて CI 待ち」に伸びる。
`check:allowlist` / `check:schema` で落ちる種類のミスは、PR 後まで分からなくなる。
