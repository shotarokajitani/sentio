# 02 State層（会社モデル＝長期記憶）

Claudeは「記憶する装置」ではなく「記憶を読んで考える装置」。記憶はDBに置く（モデル差替可・監査可・削除可）。

## 4構成
1. entities: 顧客/従業員/商品/競合/仕入先/固定費。名寄せキー（法人番号・ドメイン・メール・正規名）。
   従業員には用途制限フラグ（評価・査定文脈での出力禁止）を構造として持つ。第三者の氏名等はここのみ。
2. baselines: 指標×エンティティ(任意)×粒度ごとの「この会社の平常」（曜日・季節調整、頑健統計）。
   最低観測数未満はベースライン未成立＝検知対象外（構造で誤検知を防ぐ）。成立数＝カバレッジ＝「見える範囲」。
3. narratives: dialogue由来の懸念・意図・判断＋学習（company_learningsの信頼度upsert方式を統合）。
   confidenceは時間減衰。訂正は即時減算し、訂正自体もdialogueイベントとして残す（監査可能性）。
4. company_summary: 章立て固定・トークン上限固定の自然言語サマリー（夜間再生成）。全エージェント呼び出しに常備注入。

## 圧縮階層とトークン予算
上層=summary（常時）/ 中層=baselines・entities関連分（構造化）/ 下層=生イベント断片（調査対象のみ）。

## 記憶パケット編成器（想起の一元化）
Investigator・「Sentioに聞く」・週次生成は同一編成器経由。常備＋関連ベースライン＋関連narratives＋裏付け断片を
合計上限内で優先度順に詰める。想起の一元化で回答の食い違いを構造的に防ぐ。

## 記銘の規律（3経路のみ・自由文追記禁止）
(a) baselines夜間再計算（決定的） (b) narratives upsert（confidenceルール付き） (c) summary再生成（章立て・上限で拘束）

## コールドスタートと忘却
Day0はURL解析metadata＋外部データでsummary初版を生成。解約後180日完全削除（トークンは即時削除の例外→05）。
従業員は退職検知（勤怠・アカウント無効化）で新規蓄積停止。
