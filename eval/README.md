# eval/ — エンジン評価スイート（賢さの回帰テスト）

- golden/: 入力固定（合成会社タイムライン断片＋記憶パケット）→ 期待Finding の対。1ケース=1ディレクトリ
- 実行: pnpm run eval:engine → 検知率（D1）・誤検知率（D2・陰性コントロール含む）・
  golden の meta.json と仕込みの突き合わせ・Day0 成果物の再発防止条件を検査する
- **ルーブリック採点は未実装**（スライスE の E-D4）。Evaluator（5基準）はこのスイートでは動かない。
  Investigator / Day0 / LLM もこのスイートを通らない。動くのは `runScan`（Scanner・LLMなし）だけである。
  実装するなら LLM を伴うのでスライスを分ける。**宣言だけ先に置かない**
- 検知の判定は `evidence_event_ids` と仕込みの `eventIds` の交差で行う（E-D1）。
  型の一致だけで検知扱いにしない。1つの候補は最大1つの仕込みにしか使えない
- 合格線はスライス契約が定義（slice-01: 陽性7件中6以上・誤検知≤2）
- prompts/ の変更PRは本スイートの結果添付が必須（prompts/README参照）
- 実顧客データをゴールデンセットに入れない。合成会社のみ
- ゴールデンセットにはlangフィールドを最初から持たせる（スライス1はjaのみ。多言語展開時にLauda形式と互換）
