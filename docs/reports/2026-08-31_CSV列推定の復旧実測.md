# CSV 列推定が本番で復旧した（2026-08-31・検収者）

`/connect` の入出金CSVは 2026-08-30 から落ちていた。**原因は2段階あった。**

| # | 原因 | 画面に出ていたもの |
| --- | --- | --- |
| 1 | Vercel に `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` が未設定 | 「列の対応を推定できませんでした。別のCSVでお試しください。」 |
| 2 | 発行した鍵が identity-linked で、`anthropic-workspace-id` を要求された | 同上 |

**どちらも画面には同じ1文しか出ない。** 原因はランタイムログにしか無かった。

## 復旧の実測（2026-08-31 11:4x JST・本番）

workspace 発行の鍵に差し替えて Redeploy 後、本番の `/api/csv/analyze` を
ブラウザの同一オリジンから叩いた（**実ファイルは投入していない。ヘッダーと型統計だけ**）。

**段階1: 設定の到達確認（トークンを1つも使わない探り）**

```
POST /api/csv/analyze  {}
→ 400 {"error":"headers required"}
```

**500 ではなく 400 が返る。** すなわち `route.ts:14-20` の設定チェックを通過している。
未設定のときは 500 `ANTHROPIC_API_KEY / ANTHROPIC_MODEL not set` になる（2026-08-30 実測）。

**段階2: 実際に LLM を通す**

銀行明細の形（取引日 / 摘要 / お支払金額 / お預り金額 / 差引残高）の
ヘッダーと型統計を渡した。

```
status 200
所要 30,105 ms
{"mapping":{"date":"取引日","description":"摘要","amount":null,
            "direction":null,"credit":"お預り金額","debit":"お支払金額",
            "balance":"差引残高"}}
```

**マッピングは正しい。** 入金額・出金額が別列の形を、`amount` / `direction` を null にして
`credit` / `debit` に振り分けている（`route.ts` のプロンプトが指示しているとおり）。

**30秒かかっていることが LLM を実際に通った証拠**でもある
（`a2_misjudgment` の「生成時間135ms」と同じ見方）。

## 新しく見えた懸念（**未着手・記録のみ**）

**30秒は遅い。** 列数がこれより多い実ファイルでは、Vercel の関数タイムアウトに
当たる可能性がある。当たった場合、利用者に見えるのは**また同じ1文**である。

- タイムアウト値の確認と、超過時に「時間切れ」と分かる文言を出すこと
- そもそも `max_tokens: 512` の JSON 1個にこの時間が要るのかの確認

**どちらもこの記録の範囲外。** 実ファイル投入で再現するかを先に見る。
