# 10 概観：Sentioは「会社」をどう理解するか（正本）

更新: 2026-07-23 / 個別機能の議論はまず本書のどの段の話かを位置づけてから行う。

## ピラミッド（下から積む）

### 第-1段｜接続層

接続は組織単位・管理者1回・従業員の作業ゼロ。従業員のデータを含む接続の有効化には、
従業員向け告知（存在・目的・本文非取得の3点／「日報と会議を減らします」テンプレ）の送付を
必須ステップとする。経営者本人のみのデータ接続（例: 本人カレンダー）には告知不要。
組織一括の正規経路: Google Workspaceドメイン委任（審査要件は要確認・07）／M365管理者同意／
Slack・CWワークスペースOAuth／勤怠・会計は元来会社単位。
組織構造は入力させない: Workspaceディレクトリ・勤怠部署・Slackプロフィールから自動取得（従）＋
行動からの推定（主）＋任意CSVインポート（一度きり・エディタは作らない）。
実態と公式のズレ（組織図上の役割と行動の乖離）はシグナル候補だが、個人評価に最も転びやすい
出力のため統制3原則を最厳格適用。

### 第0段｜個の平常

全メンバー・全指標は本人の過去とだけ比較（自己相対・曜日季節調整・最低観測数未満は対象外）。
ライフサイクル: 入社=ベースライン未成立として自動的に検知対象外／異動=役割変化検知で該当指標を
再学習期間へリセット／退職=新規蓄積停止（既定）。
休暇と途絶: 勤怠接続済みなら休暇中は個人系走査を停止。休暇種別（病休・産休等）はFinding本文に
書かない（「不在期間中」とのみ）。勤怠未接続の縮退形は下表参照——推定に留まる間、個人単位の
途絶Findingは出さない（会社・チーム集計のみ）。個人途絶シグナルの解禁条件=勤怠接続。
カレンダータイトルは「準本文」: 検知の材料（社内外判別・相手）には使うが、機微カテゴリ
（医療・宗教・採用候補者名・明白な私事）を検出した予定はS2相当に格下げし、タイトルの
本文・Finding引用を禁止。

### 第1段｜役割の文脈

同じ逸脱でも役割で意味と重みを変える（営業の外部会議減=候補／経理の同事象=非候補）。
役割は排気から推定し確度付きで保持。低確度は経営者に1タップ確認（頻度統制内）。断定しない。

### 第2段｜関係の網

内部網（誰と誰のやり取りの太さ・途絶）と外部網（外部接点の集中=クライアント依存）。
個々が平常でも網の形の変化が会社の変化。材料はメール/Slackメタデータ＋カレンダー共起。

### 第3段｜会社のリズムと翻訳

売上・資金・繁閑の周期、経営者の関心（narratives）。下段の変化をこの文脈で
「会社にとっての意味」に翻訳したものだけがFindingになる。

## 統制3原則（全段共通）

1. 上に行くほど寡黙に: 下段の走査量は増えてよいが、第3段の出力は週2件・文字数上限を不変とする。
   走査本数の増加に対し発火閾値を統制（多重比較対策）。
2. 確度は減衰せず継承: 推定（役割70%等）の上に断定を積まない。Finding文面まで確度を引き継ぐ。
3. 人を評価しない: 個人はケア文脈でのみ出力。網の分析も常に「会社の状態」の語彙で書く。

## 縮退規律（必須）

全機能は「利用可能なデータだけで成立する縮退形」を持ち、無いデータは代替せず
「見えていない」と申告する。未接続データ源への依存を縮退形なしで設計・実装することを禁止
（schema-reviewer検査対象）。カバレッジ表示は本表から導出する。

| 機能             | 本則データ       | 縮退形（現在）                                                                  |
| ---------------- | ---------------- | ------------------------------------------------------------------------------- |
| 途絶走査（個人） | 勤怠＋メッセージ | 出さない（解禁条件=勤怠接続）。会社/チーム集計のみ                              |
| 休暇の把握       | 勤怠             | カレンダー終日予定＋全チャネル同時沈黙による弱推定（個人Finding抑制のみに使用） |
| 役割認識         | ディレクトリ     | 行動推定＋経営者1タップ確認（これが主・恒常）                                   |
| 網（第2段）      | メール/Slackメタ | カレンダー会議共起の粗い網＋「網はまだ粗い」表示                                |
| 会計分析         | 会計仕訳         | 銀行明細（勘定科目なし・粗い）＋確度表示                                        |
| Day0出口         | 全ブロック       | Evaluator通過ブロックのみ表示（2未満なら送信しない）                            |
| 週次出口         | Finding          | 安定＋カバレッジ＋続報中心（キー羅列禁止・文章で）                              |

## 暫定（要承認・07登録）

A. 対象範囲: 雇用形態を問わず「組織のワークスペース参加者全員」に同一の保護と開示（推奨案）
B. 閲覧ロール: 経営者=全量／幹部=枠単位の共有許可範囲（組織系は含まない）／
オンボーダー=運用必要範囲・監査ログ付き
C. 個人からの開示・削除請求対応: 個人単位エクスポート・削除機能（会社180日削除の個人版）
