# PS-9c の改訂（2026-09-13・検収者の決定）

**正本は契約PS である**（`claude/Sentio_契約PS_20260903.md`。このリポジトリには無い）。
ここにあるのは、実装側で参照するための改訂文の写しと、実装との対応である。
契約PS 本体の更新は検収者が行う。

## 改訂前

> 取り込みが止まっている会社には `state-baselines` も `run-sense` も呼ばない。
> 取り込みが止まっている会社に平常の状態記述を出すと、古い値を今の状態として提示することになる。
> 同時に、この経路は LLM へ入らない。呼ばないことが担保である。

## 改訂後

> **取り込みが止まっている源の値を、今の状態として提示しない。**
> 源ごとに判定し、止まっている源は本文で「○月○日から取れていません」と明示する。

## なぜ改訂したか

改訂前は**会社単位**で止めていた。Google カレンダーの連携が `revoked` になると、
その会社は「再連携のお願い」だけを受け取り、**CSV 由来の処理まで一緒に止まっていた。**

本番の実測（2026-09-12）では、CSV 59行を持つ会社が 09-08 に Google 連携を失って以来、
毎回 `reconnect_suppressed` で終わり、**入出金の平常値が一度も確立していない。**

**カレンダーが切れても、入出金の取り込みは止まっていない。**
源ごとに鮮度が違うので、会社単位で止めると生きている源の値まで捨てることになる。

改訂前の意図（古い値を今の状態として出さない・LLM へ入れない）は、**源の単位で守る。**

## 決まったこと

| 項目                  | 決定                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| 判定の単位            | データ源ごと                                                                                                  |
| Google が止まったとき | sync・予定の走査・`schedule_interval` の更新を止める                                                          |
| CSV が生きているとき  | 入出金の走査・`inflow` / `outflow` / `revenue` の平常値・入出金の本文は続ける                                 |
| CSV の鮮度            | 最後の取り込みから **45日**を過ぎたら止まっている源（月1回の取り込みを想定）。**Google だけを特別扱いしない** |
| 本文                  | 止まっている源に依存する項目は出さず、1行「カレンダーは 9月8日から取れていません（再連携はこちら）」          |
| 再連携のお願い        | 生きている源があるときは**別のメールで送らない**。毎朝のメールの中の1行にする                                 |
| LLM への入力          | 止まっている源の値は入れない。生きている源だけで候補が出るなら投資してよい                                    |
| 生きている源が0の会社 | 従来どおり（再連携のお願いだけ／源が無ければ skipped）                                                        |
