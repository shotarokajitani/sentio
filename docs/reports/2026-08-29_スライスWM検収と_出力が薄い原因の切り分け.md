## 2. 「出力が薄い」原因は ②データ量 だった（③文面ではない）

今日ずっと切り分けられていなかった3つの原因のうち、**①は潰れ、②と③の切り分けもついた。**

| 原因 | 判定 |
| --- | --- |
| ① 出力が `baselines` を読んでいた | **潰した**（スライスWM） |
| ② データが薄い | **これが本体** |
| ③ 文面の設計 | **問題ではなかった** |

### 根拠 — 2026-07-29 の Day0 レポート（合成会社「株式会社アオバ製作所」）

同じ `notice@sentio-ai.jp` から届いていた過去のメール。**件名が発見そのものになっている。**

> 入出金明細では入金13件・合計¥1,731,000とある一方、月別内訳では11ヶ月連続で入金¥0でした

本文:

> 入出金データによると、全体集計では入金13件・合計¥1,731,000が記録されている一方、
> 月別内訳では2025年8月〜2026年7月まで一貫して入金¥0・出金のみが続いています
> 気になる点: 月次の資金繰りが出金超過で推移している点が、経営判断上気になる箇所です

**「同じデータの2つの見方が食い違っている」という発見である。**
誰も報告していないのに会社の状態が一行で立ち上がっている。北極星そのもの。

**エンジンは既に書ける。** サイト・カレンダー・入出金が揃った瞬間にこれが出た。
カレンダー20件だけでは突き合わせる相手がいないから薄いのであって、
**文面設計の問題ではなかった。**

### コードを読んだ結果（2026-08-29）— **送信側の不具合ではない**

`supabase/functions/_shared/mailer.ts:78-88` は、件名を
`JSON.stringify` で Resend の API に渡しているだけである。

```ts
body: JSON.stringify({
  from: config.from,
  to: [message.to],
  subject: message.subject,
  ...
}),
```

**文字コード変換も MIME エンコードもしていない**（`charset` / `base64` / `Buffer` は0件）。
UTF-8 のまま渡り、MIME 化は Resend 側が行う。**ここで化ける経路が無い。**

件名は `day0/index.ts:977` の `` `[Sentio] Day0レポート: ${company_name}` `` で、
`company_name` は**リクエストボディから来る**。したがって化けていたのは
**入力（合成会社の投入時の `company_name`）**であって、送信処理ではない。

同日20分後の3通目が正常なのも、投入をやり直したと考えると辻褄が合う。

**ただしこれは推論であり、7月に実際に何を渡したかは確認していない。**
`company_name` の投入経路（`.claude/skills/synthetic-company`）に
Shift-JIS のファイルを UTF-8 として読む経路が無いかは**未確認**。
実データで日本語の会社名を扱う前に、そこだけは見ておくこと。
