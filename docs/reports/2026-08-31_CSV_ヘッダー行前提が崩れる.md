# CSV 取り込みは「1行目が列名」を無条件に前提している（2026-08-31・検収者）

**そして前提が崩れたとき、口座番号と口座名義が Anthropic API のプロンプトに入る。**

## 何が起きたか

梶谷さんが実ファイルを `/connect` に投入し、
「列の対応を推定できませんでした。別のCSVでお試しください。」が出た。

Vercel のログ:

```
02:21:27  POST /api/csv/analyze  400   ← 検収者の探り（headers なし）
02:22:26  POST /api/csv/analyze  200   ← 検収者の探り（銀行明細の形・正しくマッピング）
02:24:04  POST /api/csv/analyze  500   ← 実ファイル
```

`get_runtime_errors` の例外クラスタは**0件**。例外ではなく、
`src/app/api/csv/analyze/route.ts` が自分で 500 を返している。

```ts
const jsonMatch = text.match(/\{[^}]+\}/);
if (!jsonMatch) {
  return NextResponse.json({ error: "マッピング推定に失敗しました", raw: text }, { status: 500 });
}
```

**モデルの返答に JSON が無かった。**

## 原因: そのファイルに列名の行が無い

1行目の実物（**口座番号と名義は伏せる**）:

```
1  3  0  80830  80301  80830  310  ｼﾞ-ｴﾑｵ-ｱｵｿﾞﾗﾈﾂﾄ  102  ﾎｳｼﾞﾝﾀﾞｲﾆ  0  1  <口座番号>  ｶ)<名義>  1  (空)  123821
```

これは**全銀協規定フォーマット系の入出金明細**である。特徴が揃っている。

- 先頭が `1`（データ区分＝ヘッダーレコード）
- **半角カナ**（`ｼﾞ-ｴﾑｵ-ｱｵｿﾞﾗﾈﾂﾄ` = GMOあおぞらネット、`ﾎｳｼﾞﾝﾀﾞｲﾆ` = 法人第二）
- 銀行名・支店名・口座番号・口座名義がレコードとして並ぶ
- **列名の行が存在しない**

`src/app/connect/connect-client.tsx:139` は**無条件**にこうしている。

```ts
const headers = parseCSVLine(lines[0]);
```

したがってモデルには「`"1"` という列」「`"80830"` という列」「`"ｶ)…"` という列」が渡る。
マッピングのしようがないので、モデルは JSON ではなく散文を返し、500 になった。

**「別のCSVでお試しください」は、この場合たまたま正しい助言だが、理由を何も伝えていない。**

## **より重い問題: この経路で PII がプロンプトに入る**

`route.ts` にはこう書いてある。

> Build column description for Claude (**no string cell values - PII protection**)

**この保護は「1行目が列名である」ことに依存している。**
列名は `- "${h}": 型=…` の形で**そのままプロンプトに載る**（`route.ts:34-44`）。

1行目がデータだった今回、**銀行名・支店名・口座番号・口座名義が「列名」として
Anthropic API に送られた。** 型統計のサンプル除外は文字列列にしか効かず、
**列名そのものには一切効いていない。**

- 実際に送信された（2026-08-31 02:24 の 500 のリクエスト）
- 送信先は Anthropic API（`/privacy` §4 に副処理者として記載済み）であり、
  **第三者への流出ではない**。ただし**設計が意図していない経路**である
- **仕組みで防いでいない。** 防いでいるつもりだった、が正確である

## 判断が要ること（**人間・未確定**）

| # | 論点 | 選択肢 |
| --- | --- | --- |
| 1 | 全銀協フォーマットを取り込むか | (a) 対応する（レコード区分でパースする。列推定が不要になる） / (b) 対応せず**検出して断る** |
| 2 | ヘッダー行の有無をどう判定するか | 1行目が全て数値・日付・記号なら「列名ではない」と見なす、等 |
| 3 | 列名を送る前に伏せるか | 数字だけの列名・半角カナの列名を送らない、など。**ただし列名を伏せると推定できない**。トレードオフ |

**(b) だけでも今日の事故は止まる。** 判定して断れば、プロンプトに入る前に落とせる。

## 直ちに効く回避（**梶谷さん**）

GMOあおぞらネット銀行は**列名付きの入出金明細CSV**も出せる。
そちらを出し直せば、いまのコードで通る見込みが高い
（検収者の探りで銀行明細の形は 200 で正しくマッピングされている）。

## 併せて直すべき文言

「列の対応を推定できませんでした。別のCSVでお試しください。」の1文が、

- 鍵が無い（500）
- 鍵が identity-linked（500）
- モデルが JSON を返さなかった（500）
- **1行目が列名でない（今回）**

**の4つを全部飲み込んでいる。** 昨日から今日で、この1文の裏に3つ別の原因があった。
`raw` を持っているのに捨てている。**原因が画面から消える作りになっている。**
