# スライスRF — `/report` が月曜に空になるのを止める（直近の実績がある週へのフォールバック）

- 状態: **active**（2026-08-31 梶谷さん承認）
- 起草: 2026-08-31（検収者）
- 背景: `docs/reports/2026-08-31_report が月曜に必ず空になる.md`
- 前提: スライスW クローズ済み（`docs/contracts/slice-weekly-report.md`）

## なぜやるか

**`/report` は毎週月曜に必ず空になる。** 実測で確認した（2026-08-31 00:35 JST）。

2つの仕様が噛み合っていない。

| 仕様 | 出所 |
| --- | --- |
| `/report` は**当週固定** | 契約 スライスW の W-D1 |
| `sync-connections` は `timeMin = now - 7日` / **`timeMax = now`** | `supabase/functions/sync-connections/index.ts:188-196` |

**`timeMax = now` なので未来の予定は同期されない。**
初回連携（`src/app/auth/callback/google/route.ts:130`）も同じく `timeMax = now`。

したがって月曜の朝は当週にまだ過ぎた予定が無く、**構造的に0件**になる。
週が進むにつれ埋まり、翌月曜にまた空へ戻る。**毎週この鋸歯が出る。**

さらに Google OAuth 審査に提出済みのテスト資格情報にこう書いてある。

> the weekly report at https://sentio-ai.jp/report **is populated when you sign in.**

**審査者が月曜・火曜午前にログインすると、この記述は嘘になる。**
審査は4〜6週間かかるので、その窓は5〜6回訪れる。

## 決定

| # | 論点 | 決定 |
| --- | --- | --- |
| **RF-D1** | 当週が0件のときどうするか | **直近の「会議がある週」を出す。** 何週前を出しているかを**画面に明示する** |
| **RF-D2** | W-D1（当週固定）との関係 | **W-D1 を上書きする。** 既定は当週のままで、**当週が0件のときだけ**遡る。契約 スライスW の W-D1 に本契約への参照を追記する |
| **RF-D3** | どこまで遡るか | **最大8週。** それでも0件なら**遡らず当週の空状態を出す**。無限に遡って「半年前の週」を今週として見せない |
| **RF-D4** | 未来の週 | **遡るだけ。未来の週は絶対に選ばない**（同期されていないので出せる訳がなく、出たらバグである） |
| **RF-D5** | 前週比 | **表示している週の前週と比べる。** 当週と比べない。「8/24の週」を出しているなら比較相手は「8/17の週」である |
| **RF-D6** | `deliver-weekly`（メール） | **変更しない。** メールは ISO 週を冪等キーに使っており（`weekly:<company_id>:<ISO週>`）、対象週を動かすと過去の配信記録と衝突する。**画面とメールで意味が分かれることを承知のうえで分ける** |
| **RF-D7** | `sync-connections` の `timeMax` | **変更しない。** 未来の予定を取り込むかは別の判断（`docs/spec/07_open_items.md` に登録する）。**このスライスは見せ方だけを直す** |

## 実装の形（**純関数に寄せる。DB 側で週を決めない**）

集計の正本は `shared/report/weekly.ts` の純関数である（スライスWM の WM-D1）。
**週の選択もここに置く。** `src/lib/report/events.ts` は窓を広げて渡すだけにする。

```
shared/report/weekly.ts
  + export const FALLBACK_MAX_WEEKS = 8;
  + export function resolveWeekReference(rows: EventRow[], now: Date): Date
      当週に会議が1件でもあれば now をそのまま返す。
      無ければ1週ずつ遡り、会議が1件以上ある最初の週の基準時刻を返す。
      8週遡って見つからなければ now を返す。
  ~ WeeklySummary に isFallback: boolean を足す

src/lib/report/events.ts
  ~ 取得窓を「当週の8週前の週頭」から「当週の終わり」へ広げる
    （前週比のためにさらに1週前まで必要なので実際は9週前の週頭）
  ~ resolveWeekReference で基準を決めてから summarizeWeek に渡す

src/app/report/report-view.tsx
  ~ isFallback のとき、数字の上に一文出す
```

**`summarizeWeek` のシグネチャは変えない。** 呼び出し側が渡す `reference` が変わるだけである。
これで `deliver-weekly`（RF-D6 で対象外）に影響が出ない。

## 文言（i18n・`src/i18n/ja.ts` の `report`）

```ts
fallbackNotice: "今週はまだ予定がありません。直近の実績を表示しています。",
scheduleHeading: "今週の予定",          // 遡っていないとき（現状のまま）
fallbackScheduleHeading: "この週の予定", // 遡っているとき（2026-08-31 追補）
```

**「直近の実績」と明示する。** どの週かは既存の `weekRange` が上に出ているので、
**何週前かを別途書かない**（週の範囲そのものが出ている方が正確である）。

**予定リストの見出しも遡り対応にする**（`fallbackScheduleHeading`）。
**「先週の予定」と書かない。** 遡り先は最大8週前まであり、**前週とは限らない**。
何週前かを文言で断定すると嘘になる。

> **2026-08-31 追補（契約側の書き漏れ）。**
> 本番実測で、フォールバック表示中に見出しが「今週の予定」のまま
> 先週（8月24日〜27日）の予定が並んでいることが判明した。
> 起草時に `fallbackNotice` は書いたが、**`scheduleHeading` を遡り対応にするのを書き漏らした。**
> 数字と注意書きだけ直しても、リストの見出しが残っていれば読み手には今週に見える。

`title`（「今週の会社」）と `lead`（「…今週の会議の量を集計しています。」）は
**そのまま**でよい。`title` は画面名、`lead` は製品の説明であり、
`fallbackNotice` が直下で事情を説明している。**直すのは予定リストの見出しだけ。**

`emptyTitle` / `emptyBody` は**そのまま残す**。8週遡っても0件のときに使う。

## 停止点

- **merge はしない。** PR を全緑にした時点で止まって報告する
- **`sync-connections` の `timeMax` を触らない**（RF-D7）
- **`deliver-weekly` を触らない**（RF-D6）
- migration を作らない。新テーブルを作らない
- 本番 Ref `kwpldqbnkraftaahnpev` への CLI 直接操作をしない
- 遡り上限（8週）を**設定可能にしない。** 定数1つで固定する。
  可変にすると「どこまで遡ったか」が環境で変わり、実測が再現しなくなる

## 非スコープ（**やらない**）

- 期間の切り替え UI（前の週・次の週を選ぶ）。**自動フォールバックだけ**
- `sync-connections` / 初回連携の `timeMax` の変更
- `deliver-weekly` の変更
- `baselines` の利用（W-D2 のまま使わない）
- freee / CSV 由来の集計

## この契約が閉じたら分かること

**「今週まだ何も起きていない」ときに、Sentio が何を見せるべきか。**

北極星は「入力を要求しない」であって、「入力が無ければ何も出さない」ではない。
空の箱を見せるのは、経営者に**Sentio を開く理由が無い日**を作るということである。
このスライスは、その日を無くす最小の一手である。
