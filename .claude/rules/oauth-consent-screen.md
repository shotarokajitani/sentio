# OAuth 同意画面の設定は、勝手に変えない

**変更すると Google の再審査（4〜6週間）に戻る。**
`hooks-coverage.md` / `ci-coverage.md` / `verify-before-report.md` と同じく、
**守れる範囲と守れない範囲**を書く。

## なぜ作ったか

2026-09-02、**4回目の提出でようやく OAuth 審査が承認された**
（`docs/runbooks/2026-08-20_google-oauth-verification.md`）。承認メールにこの一文がある。

> You will need to submit a new verification request for access to new scopes,
> or if you make any changes to your OAuth consent screen configuration.

**設定を1つ変えるだけで、また4〜6週間が消える。**
3回の差し戻しに費やした時間を、うっかりで繰り返さないために置く。

## 何を止めるか

**OAuth 同意画面の設定変更は、人間が「再審査を受け入れる」と明示した時だけ行う。**

### 引き金になるもの

- **スコープの追加・変更**（`calendar.events.readonly` を広げる／別のスコープを足す）
- **アプリ名 / ロゴ / サポートメール / 承認済みドメイン**
- **プライバシーポリシー・利用規約の URL**

### 引き金にならないもの

- **ポリシー本文の更新。** URL が変わらなければ再審査に戻らない
  （§6 の文言を直す、条項を足す、などは自由）
- コード側で**より狭い**スコープしか要求しなくなること。
  承認済みの範囲を超えないので新しい審査は要らない

**迷ったら「Console の画面に出る項目かどうか」で切る。** 出るなら引き金である。

## 承認済みの状態（2026-09-02 時点）

```
project 228589171157 (Project ID: sentio-492313)
scope: https://www.googleapis.com/auth/calendar.events.readonly   ← 1本だけ
```

**スコープが1本しか無いことが、審査で効いた。** 同意画面に
「Show all services」ボタンが出ないのはこのためで、4回目の差し戻しは
「そのボタンを押して展開せよ」という指摘だった。**押せないことを説明して通した。**
スコープを増やすと、この説明が成立しなくなる。

## 守れる範囲: コード側のスコープ文字列

`src/app/api/auth/google/route.ts` が要求するスコープは、
`tests/unit/oauth-scope.test.ts` が**承認済みの値に固定している。**
変えると CI が赤くなる。

**赤くなったら、値を直すのではなく再審査の要否を確かめること。**
狭める分には審査は要らないが、**広げると要る。**

## 守れない範囲（設計上の限界。これは仕様であって不具合ではない）

1. **Console 側の操作は検出できない。**
   同意画面の設定は Google Cloud Console にあり、**リポジトリに痕跡が残らない。**
   hooks はツールの入力しか見えず、CI はリポジトリしか見ない。
   アプリ名を変えても、ロゴを差し替えても、**この規則を含めて誰も気づかない。**
   **担保は人間の記憶しかない。だからこそ引き金の一覧をここに置いている**
2. **コード側の固定は「要求するスコープ」しか見ない。**
   Console 側が広いまま／狭いままでも、コードが承認済みの値なら緑になる。
   3回目の差し戻し（コードと Console の不一致）は、**この検査では捕まらない**
3. **再審査が必要かどうかを機械が判定することはできない。**
   Google の運用は文書化されておらず、実際に出してみるまで分からない部分がある。
   ここに書いた引き金は**承認メールの文面と3回の差し戻しの実績**から起こしたものである

## 変えるときの作法

1. **人間が「再審査を受け入れる」と明示する。** 4〜6週間、新規の連携が止まりうる
2. `docs/runbooks/2026-08-20_google-oauth-verification.md` に、何をなぜ変えるかを先に書く
3. コード側のスコープを変えるなら `tests/unit/oauth-scope.test.ts` の期待値も更新する。
   **テストを先に直してから Console を触らない。** 順序は Console → 実測 → テスト更新である
